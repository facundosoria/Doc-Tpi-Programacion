## Descripción (Como / Quiero / Para)

- **Como:** equipo de integración (y `admin-service` como consumidor)
- **Quiero:** el contrato OpenAPI y un mock del golden set publicados
- **Para:** que `admin-service` avance su integración sin esperar al servicio real

---

## Notas / Observaciones

- **Reglas de negocio:** el contrato en el repositorio (`docs/contracts/`) describe **solo** las
  operaciones que existen; la adenda S1 se fusiona en el OpenAPI cuando `admin-service` aprueba
  el cambio.
- **Validaciones:** el OpenAPI valida contra su esquema; el mock responde con cuerpos conformes al
  contrato.
- **Datos obligatorios:** archivo OpenAPI, adenda, comando de una línea para levantar el mock,
  ubicación documentada.
- **Performance:** no aplica.
- **Seguridad:** el mock no expone datos reales.
- **Accesibilidad:** no aplica.
- **Otros:** cualquier campo que hoy no exista se **congela** con `admin-service` antes de
  publicarlo — no se agrega al contrato «por las dudas».

---

## Criterios de Aceptación (CA)

- [ ] **CA1:** el OpenAPI publicado valida y describe únicamente las operaciones implementadas
  (crear golden set, crear entrada, listar, obtener detalle).
- [ ] **CA2:** el mock se levanta con un comando documentado y responde según el contrato.
- [ ] **CA3:** la adenda S1 está revisada con `admin-service` y registrada.
- [ ] **CA4 (negativo):** un PR que agrega al contrato una operación no implementada se rechaza.
- [ ] **CA5 (negativo):** un campo nuevo sin acuerdo con `admin-service` bloquea la publicación.

---

## BDD

**Característica:** contrato y mock del golden set para consumidores.

### Escenario 1 — admin-service integra contra el mock

- **Dado:** el contrato OpenAPI y el mock publicados
- **Cuando:** `admin-service` levanta el mock con el comando documentado y prueba su integración
- **Entonces:** el mock responde conforme al contrato y `admin-service` avanza sin el servicio real

### Escenario 2 — Operación inexistente en el contrato

- **Dado:** el acuerdo de publicar solo operaciones implementadas
- **Cuando:** un PR agrega al OpenAPI una operación que el servicio no expone
- **Entonces:** la revisión rechaza el PR

### Escenario 3 — Campo no acordado

- **Dado:** un campo de respuesta que hoy no existe en el servicio
- **Cuando:** alguien intenta incluirlo en el contrato publicado
- **Entonces:** la publicación se bloquea hasta congelar el campo con `admin-service`
