# [GXX] — EP-03: Golden set y referencia humana

## Objetivo

Proveer al cuerpo docente las interfaces y APIs para crear, puntuar, versionar, consultar,
exportar y auditar conjuntos de casos de referencia (*golden set*) con sus puntuaciones
humanas en las cinco dimensiones pedagógicas de la cátedra, con persistencia inmutable y
resolución trazable de discrepancias entre docentes, de modo que exista una referencia
humana confiable para calibrar el evaluador de IA.

## Suposiciones y Restricciones

- **Suposiciones:**
  - Los docentes evalúan sobre la rúbrica oficial de plataforma **1.0** fijada por la cátedra
    (autonomía 30 %, claridad 25 %, progresión 20 %, cumplimiento 15 %, eficiencia 10 %).
  - La titularidad (*ownership*) entre docente y cohorte se resuelve por identidad delegada y
    coordinación contractual con `courses-service`.
  - Las transcripciones alumno-tutor se ingestan como **datos pasivos** (JSON plano); no se
    interpretan como instrucciones.
  - Para S2, el equipo docente aporta un **protocolo de doble puntuación** (dos docentes
    puntúan de forma independiente y resuelven diferencias antes de publicar).
- **Restricciones (legales / técnicas):**
  - Integridad de referencia: cada entrada incluye las cinco dimensiones con puntuaciones
    enteras en el rango cerrado 0–100.
  - Idempotencia en escritura: toda alta o carga exige `Idempotency-Key` (UUID) para prevenir
    duplicaciones por reintentos.
  - Aislamiento de cohorte: un docente no consulta, lista ni modifica golden sets de cohortes
    ajenas (`403` / `404`).
  - Persistencia inmutable: los datos viven en volúmenes persistentes de PostgreSQL, sobreviven
    a `docker compose restart` y las tablas de referencia son *append-only*; una versión
    publicada no se pisa ni se edita, se emite una nueva.
  - Doble ciego (S2): un docente no ve la puntuación del otro hasta enviar la suya.
  - Interfaz web con accesibilidad WCAG 2.1 AA (foco por teclado, etiquetas semánticas,
    alertas `aria-live`).

## Criterios de Aceptación a nivel Épico

- El conjunto mínimo de historias permite el flujo extremo a extremo:
  - **S1:** un docente autorizado accede a la interfaz, crea un golden set para su cohorte,
    carga un caso con transcripción y cinco puntajes, y lo recupera **idéntico** tras
    reiniciar el microservicio.
  - **S2:** dos docentes puntúan el mismo caso de forma independiente, el sistema muestra las
    diferencias por dimensión, un rol autorizado resuelve, se publica una versión inmutable
    con autor/fecha/rúbrica y se puede exportar y volver a consultar.
- KPIs iniciales alcanzan:
  - 100 % de altas con idempotencia garantizada (0 duplicados ante reenvíos).
  - Consulta de casos < 100 ms.
  - 0 llamadas directas de la UI al backend (100 % por el Gateway).
  - Una discrepancia sin resolver **no** habilita publicación.
- Sin regresiones críticas en:
  - Persistencia e inmutabilidad tras reinicio de contenedores.
  - Rechazo a nivel base de cualquier `UPDATE`/`DELETE` sobre referencias consolidadas o
    versiones publicadas.
  - Aislamiento estricto de visibilidad entre cohortes.
- Observabilidad y alertas configuradas:
  - `audit_events` registra cada creación, carga, resolución y publicación con actor
    (servicio + usuario), recurso y correlación `traceparent`.
  - Métricas de negocio: golden sets activos por cohorte, entradas cargadas, discrepancias
    pendientes de resolución.
- Documentación de uso y operación publicada:
  - Adenda contractual de Golden Set en `docs/contracts/llm-service-v1-s1-golden-set-adenda.md`,
    revisada con `admin-service`.
  - Wireframes de baja fidelidad y prototipo navegable vinculados desde las fichas de HU
    ([prototipos/wireframes-h07-golden-set.md](../prototipos/wireframes-h07-golden-set.md)).
  - Guía de ejecución paso a paso de las demos de S1 y S2.
  - Página de Wiki `GXX - GOLDEN SET` según [27](../27-guia-wiki-taiga.md).

## Dependencias / Impactos

- **Servicios / APIs:** Spring Cloud Gateway (identidad delegada y ruteo), `courses-service`
  (resolución de cohorte y titularidad docente), `admin-service` (gestión institucional).
- **Módulos afectados:** `llm-service` (`api`, `application`, `domain`, `infrastructure`,
  `security`), `llm-workbench` (frontend Angular para docentes).
- **Otros equipos:**
  - Cátedra y referentes docentes (**D02**): validación de la estructura de rúbrica y pesos,
    set base y protocolo de doble puntuación.
  - Equipo de frontend compartido: lineamientos de autenticación y componentes base.
- **Impacto en datos / migraciones:** tablas `golden_sets`, `golden_set_entries`,
  `idempotency_requests`, `audit_events` (S1); puntuación individual, resolución, versión y
  *snapshot* publicado *append-only* (S2).
- **Feature toggles / flags:** no aplica.
