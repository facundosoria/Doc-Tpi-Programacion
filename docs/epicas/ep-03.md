# G03 — Golden set y referencia humana

---

## Objetivo

Que el cuerpo docente tenga una referencia humana confiable y versionada,
con las discrepancias resueltas de forma trazable, para poder calibrar
después al evaluador de IA contra ella.

---

## Suposiciones y Restricciones

- **Suposiciones:**
  - Los docentes evalúan sobre la rúbrica oficial de la plataforma, con sus
    cinco dimensiones y pesos ya definidos.
  - Cada golden set pertenece a un docente y una cohorte concretos.
  - Las transcripciones se usan solo como datos de referencia, nunca como
    instrucciones.
  - En la segunda etapa, dos docentes puntúan cada caso de forma
    independiente y resuelven las diferencias antes de publicar.
- **Restricciones (legales / técnicas):**
  - Cada entrada de referencia incluye las cinco dimensiones puntuadas.
  - Cada alta o carga es segura ante reintentos: un caso no se puede duplicar
    por error.
  - Un docente solo puede ver y modificar los golden sets de sus propias
    cohortes.
  - Una vez publicada, una entrada no se edita ni se borra — se emite una
    nueva versión.
  - En la doble puntuación, un docente no ve la nota del otro hasta enviar la
    suya.
  - La interfaz es accesible para personas con discapacidad (estándar WCAG
    2.1 AA).

---

## Criterios de Aceptación a nivel Épico

- [ ] El conjunto mínimo de historias permite el flujo completo: un docente
  crea un golden set para su cohorte, carga un caso con su transcripción y
  sus cinco puntajes, y puede recuperarlo igual después de un reinicio del
  sistema; con dos docentes, el sistema muestra las diferencias entre sus
  puntajes, alguien autorizado las resuelve, y se publica una versión con
  autor y fecha.
- [ ] Los KPIs iniciales se cumplen: ninguna carga se duplica ante un
  reintento, las consultas son rápidas, y una discrepancia sin resolver no
  permite publicar.
- [ ] No hay regresiones en: la persistencia de los datos tras reiniciar el
  sistema, el rechazo de ediciones o borrados sobre referencias ya
  publicadas, y el aislamiento entre cohortes.
- [ ] Hay observabilidad: cada creación, carga, resolución y publicación
  queda registrada con quién la hizo, y hay métricas de golden sets activos y
  discrepancias pendientes.
- [ ] Está documentado cómo se usa: el contrato de datos acordado con el
  resto de la plataforma, los diseños de la interfaz, y una guía paso a paso
  para hacer la demo.

---

## Dependencias / Impactos

- **Servicios / APIs:** el gateway institucional, el servicio de cursos
  (para saber a qué cohorte pertenece cada docente), el servicio de
  administración.
- **Módulos afectados:** nuestro propio servicio, y la interfaz web para
  docentes.
- **Otros equipos:** la cátedra y los referentes docentes (validan la
  estructura de la rúbrica y el protocolo de doble puntuación); el equipo de
  frontend compartido (componentes base de acceso).
- **Impacto en datos / migraciones:** se crean las primeras tablas de golden
  sets, entradas y auditoría.
- **Feature toggles / flags:** no aplica.
