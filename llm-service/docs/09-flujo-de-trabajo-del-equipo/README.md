# 09 — Flujo de trabajo del equipo

Esta carpeta explica cómo convertir una tarea acordada en un cambio revisable: ramas, commits, pull requests, revisión, evidencia y cierre. Usala cada vez que inicies o finalices trabajo técnico.

## Qué vas a encontrar

1. [Gitflow](01-gitflow.md): ramas protegidas, convenciones de nombres, relación con `main` y `develop`, y reglas de integración.
2. [Workflow diario](02-workflow-diario.md): pasos prácticos desde tomar una tarea hasta abrir PR, revisar, validar y cerrar.

## Cómo leerla

Leé Gitflow una vez al incorporarte y volvé a él cuando dudes sobre una rama o integración. Usá el Workflow diario como checklist antes de cada PR. Ambos documentos se aplican junto con la historia o tarea de `07`, los contratos afectados y las pruebas de `06`.

## Qué no reemplaza

El flujo Git no define el alcance ni los criterios de aceptación. Antes de abrir una rama, asegurate de que la tarea tenga fuente de verdad, contrato si aplica y evidencia de prueba prevista.
