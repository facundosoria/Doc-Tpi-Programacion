Pregunta 1

¿Cuál es nuestro objetivo?

Inteligencia artificial pedagógica y evaluativa con rigor académico y costo controlado.

1

Tutor Socrático en Vivo

Asiste al estudiante en el IDE mediante preguntas guía y pistas conceptuales. Un inspector AST bloquea cualquier fuga de la solución.

🎯 Meta: Guía pedagógica sin regalar el ejercicio.
2

Evaluación Analítica 5D

Calcula un score de 0 a 100 puntos. El 45% del puntaje se calcula de forma 100% determinística en Java (inmune a jailbreak y alucinación).

🎯 Meta: Evaluación justa, reproducible y auditable.
3

Calibración Académica (Golden Set)

Ningún curso se activa sin aprobar el Golden Set con índice Kappa de Cohen ≥ 0.70 frente a 30 muestras corregidas por docentes.

🎯 Meta: Alineación matemática con el criterio del profesor.
4

Sustentabilidad y Moderación

Modera mensajes de chat en < 300 ms y aplica cuota diaria por alumno (Token Bucket) para gastar < $15 USD en el cuatrimestre.

🎯 Meta: Plataforma segura, protegida y viable en costos.

Pregunta 3

¿Cómo lo vamos a hacer? (Arquitectura)

Pipeline híbrido: sincrónico para asistencia y asincrónico para evaluación.

Flujo Sincrónico (Tutor IDE)

1. Request con JWT vía API Gateway (< 50 ms)
2. Validación de cuota diaria (Token Bucket)
3. Búsqueda RAG en pgvector (top-3 chunks del apunte)
4. Inferencia Groq/Gemini + Filtro AST anti-fuga
⚡ Latencia garantizada: < 2.0 segundos

Flujo Asincrónico (Evaluador Batch)

1. Llega evento intento_cerrado por RabbitMQ
2. Cálculo Determinístico (45%): tests y linters
3. Juicio LLM (55%): claridad, autonomía y progresión
4. Publica evento score_de_ia_calculado con trace_id
🛡️ Resiliencia total con colas de reintento Dead Letter (DLQ)

Pregunta 6

¿Por dónde vamos a hablar? (Canales & Protocolos)

Dos canales estrictamente separados con garantías específicas.

Canal 1 Sincrónico (HTTP REST)

API Gateway + OpenAPI (REST)

Nadie llama a la IA directo. Todas las peticiones pasan por el API Gateway con JWT validado (RS256).

6 Endpoints públicos (/ai/{funcion}, /ai/calibracion)
Errores estándar RFC 7807 con código tipado
Headers obligatorios: X-Trace-Id, X-User-Id
⚡ Usado por: Tutor en IDE (< 2s) y Moderador (< 300ms)
Canal 2 Asincrónico (Event-Driven)

RabbitMQ (Bus de Eventos)

Desacople total y resiliencia. Las evaluaciones pesadas viajan por colas de eventos sin bloquear al usuario.

Consumimos: intento_cerrado, curso_archivado
Publicamos: score_de_ia_calculado, calibracion_aprobada
Trazabilidad: Mismo trace_id de inicio a fin
🛡️ Usado por: Evaluador batch y alertas de seguridad
Pregunta 7 (Parte 1)

¿Cómo solucionamos cada Rol?

Mecanismos técnicos para Tutor, Evaluador y Moderador.

Asistente (Tutor)

1. Recupera contexto del apunte con RAG semántico.
2. El prompt responde con preguntas socráticas.
3. Un analizador AST (JavaParser) intercepta la salida para evitar fugas de código.

🛡️ Regla: Cero fuga de código.

Evaluador Analítico

1. 45% Determinístico en Java: Tests unitarios, linters y tiempo.
2. 55% Juicio LLM: Claridad, autonomía y progresión.
3. Genera justificación detallada por dimensión.

🛡️ Regla: Inmune a jailbreaks.

Moderador de Chat

1. Capa 1: Lista negra Trie $O(1)$ (< 1 ms).
2. Capa 2: Heurísticas Regex de patrones tóxicos.
3. Capa 3: Mini-LLM clasificador ultrarrápido.

🛡️ Regla: Latencia total < 300 ms.
Pregunta 7 (Parte 2)

¿Cómo solucionamos cada Rol? (Gobierno)

Mecanismos técnicos para Auditor, Docente y Estudiante.

Auditor (Calibrador)

1. Ejecuta el Golden Set (30 muestras docentes).
2. Calcula concordancia con Kappa de Cohen.
3. Si Kappa ≥ 0.70 aprueba; si no, emite alerta y bloquea el curso.

🛡️ Calibración académica verificable.

Docente / Admin

1. Ingesta automática de apuntes (POST /ai/ingesta).
2. Panel visual para revisar discordancias de notas.
3. Monitoreo en tiempo real de gasto en USD y tokens.

🛡️ Control total de contenido y costo.

Estudiante

1. Recibe feedback explicativo y formativo.
2. Cuota diaria (Token Bucket): Límite de consultas para evitar dependencia del LLM.
3. Visualización clara de la rúbrica.

🛡️ Aprendizaje activo y guiado.
