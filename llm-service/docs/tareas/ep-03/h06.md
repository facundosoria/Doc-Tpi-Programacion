### T1 — Caso de uso «listar»

- **Específica:** implementar el listado paginado (`page` desde 0, `size` entre 1 y 100),
  ordenado por fecha de creación descendente, con el filtro por cohorte siempre aplicado.
- **Medible:** el listado respeta `page`/`size` y el orden; una cohorte ajena no aparece.
- **Alcanzable:** 4 h, una persona de P5.
- **Relevante:** primera mitad de la lectura y el aislamiento entre cohortes.
- **Acotada:** 4 h · paso *caso de uso*. **Depende de:** H04 · **Traza:** CA3, CA4 de H06.

### T2 — Caso de uso «detalle»

- **Específica:** implementar el detalle (golden set + `entries[]`); una cohorte ajena o un
  `goldenSetId` inexistente devuelven `404`, nunca `500`.
- **Medible:** el detalle de un golden set propio trae sus entradas; uno ajeno o inexistente → `404` *Problem Details*.
- **Alcanzable:** 4 h, una persona de P5.
- **Relevante:** segunda mitad de la lectura + dos criterios negativos.
- **Acotada:** 4 h · paso *caso de uso*. **Depende de:** T1 · **Traza:** CA1, CA4, CA5 de H06.

### T3 — Autorización de lectura y validación de paginación

- **Específica:** aplicar a la lectura el mismo scope y usuario delegado que la escritura; un
  `size` fuera de 1–100 devuelve `400`.
- **Medible:** sin scope/usuario delegado → `403`; `size=500` → `400` y sin datos.
- **Alcanzable:** 3 h, una persona de P5.
- **Relevante:** criterio negativo de paginación y de seguridad.
- **Acotada:** 3 h · paso *seguridad y resiliencia*. **Depende de:** T1 · **Traza:** CA6 de H06.

### T4 — Prueba de integración de persistencia (reinicio)

- **Específica:** prueba de integración que hace `docker compose restart` y verifica que la
  consulta devuelve exactamente lo cargado antes.
- **Medible:** tras el reinicio, la respuesta `200` contiene el golden set y la entrada tal como se cargaron.
- **Alcanzable:** 3 h, una persona de P5.
- **Relevante:** es el corazón de la demo de S1.
- **Acotada:** 3 h · paso *prueba E2E*. **Depende de:** T2, H02·T1 · **Traza:** CA1, CA2 de H06.

> **Total H06:** 14 h.
