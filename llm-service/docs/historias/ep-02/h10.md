## Descripción (Como / Quiero / Para)

- **Como:** equipo de desarrollo del `llm-service`
- **Quiero:** un puerto (interfaz) para invocar modelos de lenguaje, con un adaptador simulado y
  validación estricta del formato de salida
- **Para:** que ninguna función de IA dependa de un proveedor concreto, y se pueda desarrollar y
  probar sin llamar a un proveedor real ni pagar por eso

---

## Notas / Observaciones

- **Reglas de negocio:** la interfaz de invocación vive en `domain`/`application` y no importa el
  SDK de ningún proveedor (regla del ADR, H01). El adaptador real usaría `RestClient` con timeout
  configurado; en S1 solo existe el **adaptador fake** (WireMock o equivalente), que devuelve
  respuestas fijas o basadas en reglas simples. La tabla `función → proveedor + modelo` arranca con
  una sola fila; cambiarla no exige recompilar ni re-desplegar código (RF-IA-11).
- **Validaciones:** la respuesta del adaptador se valida contra un schema estricto de salida antes
  de devolverse; una respuesta que no cumple se rechaza, nunca se "completa" a mano.
- **Datos obligatorios:** función que invoca, prompt (tratado siempre como dato, nunca como
  instrucción del sistema), timeout configurado.
- **Performance:** el timeout por defecto queda documentado y es configurable; una demora del
  adaptador no bloquea al resto del servicio.
- **Seguridad:** en S1 solo corre el fake, sin credenciales reales. Las credenciales de un proveedor
  real, cuando exista, viven fuera del repositorio (ADR, H01) — se resuelve antes de S3
  ([08 · B-6 y C-2](../../08-decisiones-y-pendientes.md)).
- **Accesibilidad:** no aplica (sin interfaz de usuario).
- **Otros:** este ítem **no forma parte del criterio de demo de S1** (esa demo sigue siendo el
  golden set). Es preparación de EP-02 para que S3 no arranque de cero.

## Criterios de Aceptación (CA)

- [ ] **CA1:** existe una interfaz de invocación de modelos en el código que **no** importa ningún
  SDK de proveedor concreto desde `domain`.
- [ ] **CA2:** un adaptador fake responde a través del puerto con datos simulados, sin llamar a
  ningún proveedor real.
- [ ] **CA3:** existe la tabla `función → proveedor + modelo` con al menos una fila; cambiarla no
  exige recompilar ni re-desplegar código.
- [ ] **CA4 (negativo):** una respuesta del adaptador que no cumple el schema estricto de salida se
  rechaza con un error controlado, no se propaga como si fuera válida.
- [ ] **CA5 (negativo):** una llamada que excede el timeout configurado se corta y devuelve un error
  controlado, sin colgar el hilo que la esperaba.

## BDD

**Característica:** invocación de modelos desacoplada del proveedor concreto.

### Escenario 1 — La función invoca a través del puerto (camino feliz)

- **Dado:** el puerto configurado con el adaptador fake
- **Cuando:** una función de IA pide una respuesta a través del puerto
- **Entonces:** el adaptador fake responde con datos simulados que cumplen el schema esperado

### Escenario 2 — Respuesta fuera de formato

- **Dado:** el adaptador fake configurado para devolver una respuesta que no cumple el schema
- **Cuando:** la función invoca al modelo
- **Entonces:** el puerto rechaza la respuesta y devuelve un error controlado, no el dato inválido

### Escenario 3 — Timeout del proveedor

- **Dado:** el adaptador simulando una demora mayor al timeout configurado
- **Cuando:** la función invoca al modelo
- **Entonces:** la llamada se corta al cumplirse el timeout y devuelve un error controlado
