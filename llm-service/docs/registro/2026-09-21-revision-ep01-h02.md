# Revisión de EP-01 · H02 tras la integración `main` → `dev` — 2026-09-21

## Decisión anterior

H02 figuraba 🟢 (evidencia del 2026-09-16, Windows): `docker compose up` dejaba PostgreSQL y
`llm-service` *healthy*, sin Kafka, y el arranque en frío medía 19 s.

## Motivo

Se ejecutó `docker compose up --build --wait` real en macOS. Levanta bien, pero: exige
`LLM_CREDENTIALS_MASTER_KEY` y la red externa `tpi-platform` (no documentadas); incluye `kafka-local`;
`smoke-compose.sh` fallaba por `container_name` fijo y redes de otro proyecto; el arranque en frío
pasó a 204 s.

## Regla vigente

- El README lista las precondiciones del primer arranque.
- `scripts/smoke-compose.sh` es autocontenido (override temporal, clave descartable).
- `.dockerignore` excluye `docsV2`.
- El contenedor del servicio se llama `llm-service` (era `tpi-llm`, nombre del repo) en `compose.yaml`,
  `compose.mesh.yaml` y `compose.server.yaml`, igual que el Eureka Service ID y `spring.application.name`.

## Fuentes

Corridas del 2026-09-21: `up --build --wait`, persistencia de volumen, puerto 5432 ocupado,
red externa ausente, choque de `container_name`, `smoke-compose.sh --cold` (204 s).
