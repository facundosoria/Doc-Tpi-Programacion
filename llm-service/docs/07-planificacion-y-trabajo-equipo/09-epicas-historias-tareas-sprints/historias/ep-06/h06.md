## Descripción (Como / Quiero / Para)

- **Como:** servicio de cursos de la plataforma (`courses-service`) que necesita saber si puede habilitar el cierre definitivo de un curso
- **Quiero:** consultar al servicio de evaluaciones si ese curso tiene evaluaciones diferidas sin calcular o apelaciones abiertas sin resolver
- **Para:** evitar cerrar un curso mientras haya alumnos con entregas o reclamos pendientes — y, en caso de que los haya, recibir la lista de qué está bloqueando el cierre para poder informárselo al docente

---

## Notas / Observaciones

- **Reglas de negocio:** el cierre de un curso solo puede habilitarse cuando no quedan evaluaciones encoladas sin calcular (diferidas por cualquier causa) ni apelaciones en estado `PENDING_REVIEW` para ese curso. Si hay al menos uno de esos pendientes, la respuesta incluye `canClose: false` y la lista de los identificadores de entrega que están bloqueando, con su causa (`DEFERRED_EVALUATION` o `OPEN_APPEAL`). Si no hay ninguno, la respuesta incluye `canClose: true` con lista vacía.
- **Cómo se controla:** el endpoint es de solo lectura — no modifica ningún dato. El `courses-service` lo llama con un token de servicio (M2M) con el scope correcto antes de permitir el cierre. Si el scope no está presente o el token no es de un servicio autorizado, el pedido se rechaza con «no autorizado» (401) o «prohibido» (403).
- **Qué tiene que incluir sí o sí:** el campo `canClose` (booleano) y la lista `blockingItems` (puede ser vacía). Cada elemento bloqueante incluye el identificador de la entrega (`attemptId`) y el motivo del bloqueo (`DEFERRED_EVALUATION` o `OPEN_APPEAL`).
- **Tiempos y límites:** la consulta debe responder en menos de 3 s para no bloquear el flujo de cierre de curso. Si la consulta interna es demasiado lenta por volumen, se agrega paginación o un límite en el número de bloqueantes devueltos — a definir en Refinamiento.
- **Seguridad:** solo tokens de servicio con audience `llm-service` y scope `courses:close`, o tokens con rol administrativo de la plataforma, pueden invocar este endpoint. Un token de alumno o de docente sin los scopes correctos recibe «prohibido» (403). Un `courseId` que no existe en el registro del `llm-service` (ninguna evaluación conocida para ese curso) responde «no encontrado» (404) para no revelar si el curso existe en otros servicios.
- **Accesibilidad / UI:** no aplica — este endpoint no tiene pantalla propia; lo consume el `courses-service` de forma programática. El `courses-service` es responsable de presentar los bloqueantes de forma legible al docente en su propia interfaz.
- **Operaciones nuevas:** `GET /api/llm/v1/courses/{courseId}/evaluation-status` — consulta el estado de evaluaciones y apelaciones bloqueantes para el cierre de un curso.

---

## Criterios de Aceptación (CA)

- [ ] **CA1:** cuando un curso tiene al menos una evaluación diferida sin calcular, la respuesta incluye `canClose: false` y una lista con el `attemptId` y la causa `DEFERRED_EVALUATION` de cada entrega bloqueante.
- [ ] **CA2:** cuando un curso tiene al menos una apelación en estado `PENDING_REVIEW`, la respuesta incluye `canClose: false` y una lista con el `attemptId` y la causa `OPEN_APPEAL` de cada apelación bloqueante.
- [ ] **CA3:** cuando un curso no tiene evaluaciones diferidas ni apelaciones abiertas, la respuesta incluye `canClose: true` y una lista de bloqueantes vacía.
- [ ] **CA4:** la respuesta sigue el esquema acordado (`canClose`, `blockingItems` con `attemptId` y `reason`) y puede ser deserializada correctamente por el `courses-service`.
- [ ] **CA_negativo_1:** (caso que debe fallar) un pedido con un token de alumno, de docente sin scopes de servicio, o sin token devuelve «no autorizado» (401) o «prohibido» (403 Forbidden con cuerpo RFC 7807), sin revelar ningún dato de evaluaciones del curso.
- [ ] **CA_negativo_2:** (caso que debe fallar) un pedido con un `courseId` para el que el `llm-service` no tiene ninguna evaluación registrada devuelve «no encontrado» (404 Not Found con cuerpo RFC 7807).

## BDD

**Qué se prueba:** que el endpoint informe correctamente si un curso puede cerrarse, que enumere los bloqueantes cuando los hay, y que rechace tokens sin los permisos de servicio correctos.

### Escenario 1 — Curso con evaluaciones diferidas (camino que devuelve canClose: false)

- **Dado:** un curso con dos entregas cuyas evaluaciones quedaron diferidas sin calcular (por falla del proveedor o por falta de calibración)
- **Cuando:** el `courses-service` consulta el estado de cierre de ese curso con un token M2M válido
- **Entonces:** la respuesta contiene `canClose: false` y una lista con los dos `attemptId` bloqueantes con causa `DEFERRED_EVALUATION`

### Escenario 2 — Curso sin pendientes (camino que devuelve canClose: true)

- **Dado:** un curso donde todas las evaluaciones están completadas y no hay apelaciones abiertas
- **Cuando:** el `courses-service` consulta el estado de cierre de ese curso con un token M2M válido
- **Entonces:** la respuesta contiene `canClose: true` y una lista de bloqueantes vacía

### Escenario 3 — Token sin scope de servicio (caso que debe fallar)

- **Dado:** un pedido al endpoint con un token de docente que no tiene el scope `courses:close` ni es un token M2M
- **Cuando:** el `courses-service` (o cualquier llamador) intenta consultar el estado de cierre
- **Entonces:** el sistema responde con «prohibido» (403 RFC 7807), sin revelar ningún dato de evaluaciones del curso

### Escenario 4 — courseId inexistente (caso límite)

- **Dado:** un pedido al endpoint con un `courseId` para el que el `llm-service` no tiene ninguna evaluación registrada
- **Cuando:** el `courses-service` consulta el estado de cierre con un token M2M válido
- **Entonces:** el sistema responde con «no encontrado» (404 RFC 7807); el cuerpo no revela información sobre si el curso existe en otros servicios

## Dependencias / Impactos

- **Servicios involucrados:** nuevo `CourseEvaluationStatusController` (o endpoint dentro de `EvaluationController`); `EvaluationRepository` (consulta de diferidos por `courseId`); `AppealRepository` (consulta de apelaciones `PENDING_REVIEW` por `courseId`); `courses-service` como consumidor
- **Módulos afectados:** solo lectura — no modifica ninguna tabla. Requiere que las tablas de evaluaciones diferidas (`LLM-S06-H01`) y apelaciones (`LLM-S07-H01`) estén disponibles con índices por `courseId`
- **Otros equipos / aprobaciones:** el equipo del `courses-service` debe acordar el esquema de respuesta (`canClose`, `blockingItems`) y los scopes del token M2M antes de implementar — este es el contrato inter-equipos más crítico de esta historia; sin acuerdo previo, la integración falla en ambos extremos
- **Impacto en datos:** sin cambios de esquema — solo lectura. Si las tablas de evaluaciones y apelaciones no tienen índice por `courseId`, puede necesitarse una migración de índice (bajo impacto, sin cambio de datos)
- **Riesgos:** si `LLM-S06-H01` (evaluaciones diferidas) o `LLM-S07-H01` (apelaciones) no están construidas, este endpoint siempre devolverá `canClose: true` aunque haya pendientes — no implementar con datos parciales sin marcarlo explícitamente como comportamiento provisional en el contrato
