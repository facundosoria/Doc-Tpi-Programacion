## Descripción (Como / Quiero / Para)

- **Como:** plataforma (dueña del dato académico)
- **Quiero:** que la base de datos inicial del servicio quede creada con historial de cambios y
  auditoría desde el primer día
- **Para:** que el dato de referencia nazca con trazabilidad y sin que se pueda borrar ni editar por
  error

---

## Notas / Observaciones

- **Reglas de negocio:** al crear la base desde cero queda armada la rúbrica de evaluación
  **versión 1.0**, con sus **cinco dimensiones** y su peso correspondiente (autonomía 30, claridad
  25, progresión 20, cumplimiento 15, eficiencia 10), junto con las tablas para guardar el banco de
  casos de referencia, sus entradas, el control de pedidos repetidos y la auditoría.
- **Validaciones:** el dato académico solo se puede agregar, nunca editar ni borrar — cualquier
  intento de modificarlo o eliminarlo se rechaza automáticamente. Una puntuación de referencia
  incompleta (que no tenga las cinco dimensiones) o fuera de rango (0 a 100) también se rechaza. No
  puede haber dos pedidos idénticos registrados como si fueran nuevos.
- **Datos obligatorios:** versión de la rúbrica, idioma, definición de las dimensiones y sus pesos.
- **Performance:** la creación de la base corre en segundos y da siempre el mismo resultado.
- **Seguridad:** la auditoría guarda quién hizo la acción, sobre qué recurso y con qué identificador
  de seguimiento; no guarda el contenido completo de las conversaciones como texto libre.
- **Accesibilidad:** no aplica.
- **Otros:** cambiar la rúbrica exige publicar una versión nueva, nunca editar la 1.0.

- [x] **CA4 (negativo):** guardar una entrada con solo cuatro dimensiones, o con una puntuación de
  120, se rechaza.
- [x] **CA5 (negativo):** dos pedidos idénticos para la misma operación, servicio y usuario no pueden
  quedar registrados dos veces.

## BDD

**Característica:** base de datos académica versionada e inmutable.

### Escenario 1 — Creación desde una base vacía

- **Dado:** una base de datos vacía
- **Cuando:** el servicio arranca y prepara la base
- **Entonces:** existen las tablas del banco de casos de referencia y la rúbrica 1.0 con sus cinco
  dimensiones y pesos

### Escenario 2 — El dato académico no admite edición

- **Dado:** un banco de casos de referencia ya guardado
- **Cuando:** alguien intenta editarlo o borrarlo directamente
- **Entonces:** la base rechaza la operación indicando que esa información no admite cambios

### Escenario 3 — Puntuación de referencia inválida

- **Dado:** la regla de que toda entrada debe tener las cinco dimensiones con valores entre 0 y 100
- **Cuando:** se intenta guardar una entrada con solo cuatro dimensiones (o con un valor de 120)
- **Entonces:** se rechaza y no queda ningún registro
