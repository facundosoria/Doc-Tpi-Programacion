## Descripción (Como / Quiero / Para)

- **Como:** sistema (motor de moderación dentro de `llm-service`)
- **Quiero:** detectores deterministas que clasifiquen un mensaje como spam, ofensivo o intento de ocultar código en menos de 50 ms, con las reglas de detección **nunca** filtradas en los mensajes de bloqueo devueltos al cliente
- **Para:** bloquear los casos evidentes sin necesidad del clasificador contextual (que es más lento y costoso), reduciendo la latencia promedio de moderación y el consumo de recursos de IA

---

## Notas / Observaciones

- Los detectores son **deterministas** (regex, heurísticas, listas negras, detección de encoding): no usan modelos de lenguaje en este paso.
- Tres familias de detectores:
  - **Spam:** repetición de tokens, densidad de URLs, dominios en lista negra, longitud anormal.
  - **Ofensivo:** lista de términos con umbral de puntuación; el umbral es configurable por curso (política del docente).
  - **Ocultar código:** detección de Base64, hex encoding, caracteres homoglifos, bloques de código camuflados como texto plano.
- El resultado de cada detector es `PASS` / `FAIL` + `reason_code`; el orquestador agrega los resultados y emite la decisión final.
- Las **reglas concretas** (expresiones regulares, pesos) deben ser gestionadas en configuración externa y **nunca** incluirse en el mensaje de error devuelto al usuario o al `chat-service`.
- El umbral de falsos positivos debe calibrarse para que texto educativo normal (p. ej. un docente explicando cómo funciona Base64) no sea bloqueado.
- Rendimiento objetivo: p99 < 50 ms medido en el servicio; no incluye latencia de red.

## Criterios de Aceptación (CA)

- [x] **CA1:** El módulo de detección determinista evalúa un mensaje y devuelve su resultado (`PASS`/`FAIL` + `reason_code`) en menos de 50 ms (p99) bajo carga normal (≤ 100 req/s concurrentes).
- [x] **CA2:** Un mensaje que contiene texto codificado en Base64 representando código fuente es clasificado como `FAIL` con `reason_code: CODE_OBFUSCATION` en menos de 50 ms.
- [x] **CA3:** Un mensaje con alta densidad de URLs (≥ 3 URLs distintas en < 200 chars) es clasificado como `FAIL` con `reason_code: SPAM`.
- [x] **CA4:** Un mensaje con términos ofensivos que supera el umbral configurado para el curso es clasificado como `FAIL` con `reason_code: OFFENSIVE`.
- [x] **CA5:** El mensaje de bloqueo devuelto al `chat-service` **no** contiene las expresiones regulares, pesos ni ningún detalle interno de las reglas de detección.
- [x] **CA6:** Los umbrales de detección son configurables por entorno (variables de entorno o archivo de configuración) sin necesidad de redespliegue.
- [x] **CA_negativo_1:** (caso que debe fallar) Si el mensaje de bloqueo devuelto por el sistema incluye el patrón regex o la regla que activó el detector, la verificación de contrato falla — **esto no debe ocurrir nunca**.
- [x] **CA_negativo_2:** (caso que debe fallar) Un mensaje de texto educativo legítimo donde un docente explica "Base64 es una codificación que convierte binarios a texto" **no** debe ser bloqueado — si el detector lo marca como `CODE_OBFUSCATION`, el umbral está mal calibrado y el CA falla.

## BDD

**Qué se prueba:** la velocidad y corrección de los detectores deterministas; la confidencialidad de las reglas; la ausencia de falsos positivos en contenido educativo normal.

### Escenario 1 — Código en Base64 detectado y bloqueado en < 50 ms (camino feliz)

- **Dado:** que el módulo de detección determinista está activo y el mensaje contiene la cadena `"dmFyIHggPSAxOyBjb25zb2xlLmxvZyh4KTs="` (código JavaScript en Base64)
- **Cuando:** el orquestador invoca el detector de ofuscación de código con ese texto
- **Entonces:** el detector responde `{ "result": "FAIL", "reason_code": "CODE_OBFUSCATION", "detector": "base64_code", "latency_ms": <50 }` y la decisión final es `BLOCK`; el mensaje de bloqueo enviado al `chat-service` **no** incluye el patrón de detección utilizado

### Escenario 2 — Texto educativo legítimo sobre Base64 no es bloqueado (caso que debe fallar si se bloquea)

- **Dado:** que el módulo de detección determinista está activo y el mensaje dice `"Base64 es una codificación que transforma datos binarios en texto ASCII; se usa en adjuntos de email"`
- **Cuando:** el orquestador invoca todos los detectores sobre ese texto
- **Entonces:** todos los detectores responden `PASS` y la decisión final es `ALLOW`; no se genera incidente de moderación

### Escenario 3 — Regla de detección filtrada en mensaje de error (caso que debe fallar)

- **Dado:** que un mensaje es bloqueado con `reason_code: SPAM`
- **Cuando:** el `chat-service` recibe la respuesta de decisión `BLOCK`
- **Entonces:** la respuesta **no** contiene campos como `regex`, `pattern`, `rule_id` ni ninguna referencia a la regla interna que activó el bloqueo; si alguno de esos campos aparece, el test de contrato falla automáticamente
