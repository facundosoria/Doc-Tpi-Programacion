## Descripción (Como / Quiero / Para)

- **Como:** equipo de desarrollo del servicio de IA
- **Quiero:** una forma única de invocar modelos de lenguaje, con un simulador para pruebas y una
  validación estricta de que la respuesta viene bien formada
- **Para:** que ninguna función de IA dependa de un proveedor concreto, y se pueda desarrollar y
  probar sin llamar a un proveedor real ni pagar por eso

---

## Notas / Observaciones

- **Reglas de negocio:** la forma de invocar modelos no depende de ningún proveedor concreto, según
  las convenciones ya acordadas para el servicio. La conexión real usaría un cliente HTTP con un
  tiempo de espera configurado; en S1 solo existe el **simulador**, que devuelve respuestas fijas o
  basadas en reglas simples. La tabla que asocia cada función con su proveedor y modelo arranca con
  una sola fila; cambiarla no exige tocar ni volver a publicar código.
- **Validaciones:** la respuesta del simulador se valida contra un formato estricto antes de
  devolverse; una respuesta que no cumple ese formato se rechaza, nunca se completa a mano.
- **Datos obligatorios:** qué función invoca, el texto de entrada (tratado siempre como dato, nunca
  como una instrucción del sistema), y el tiempo de espera configurado.
- **Performance:** el tiempo de espera por defecto queda documentado y es configurable; una demora
  del simulador no bloquea al resto del servicio.
- **Seguridad:** en S1 solo corre el simulador, sin credenciales reales. Las credenciales de un
  proveedor real, cuando exista, se van a guardar fuera del repositorio — eso se resuelve antes de
  llegar a esa etapa del proyecto.
- **Accesibilidad:** no aplica (sin interfaz de usuario).
- **Otros:** este ítem **no forma parte del criterio de demo de S1** (esa demo sigue siendo el banco
  de casos de referencia). Es preparación para que la siguiente etapa no arranque de cero.

## Criterios de Aceptación (CA)

- [ ] **CA1:** existe una única forma de invocar modelos en el código, que no depende de ningún
  proveedor concreto.
- [ ] **CA2:** el simulador responde con datos de prueba, sin llamar a ningún proveedor real.
- [ ] **CA3:** existe la tabla que asocia cada función con su proveedor y modelo, con al menos una
  fila; cambiarla no exige tocar ni volver a publicar código.
- [ ] **CA4 (negativo):** una respuesta del simulador que no cumple el formato esperado se rechaza
  con un error controlado, nunca se pasa como si fuera válida.
- [ ] **CA5 (negativo):** una llamada que excede el tiempo de espera configurado se corta y devuelve
  un error controlado, sin dejar el proceso colgado.

## BDD

**Característica:** invocación de modelos desacoplada del proveedor concreto.

### Escenario 1 — La función invoca a través del puerto (camino correcto)

- **Dado:** el simulador configurado y listo
- **Cuando:** una función de IA pide una respuesta
- **Entonces:** el simulador responde con datos de prueba que cumplen el formato esperado

### Escenario 2 — Respuesta fuera de formato

- **Dado:** el simulador configurado para devolver una respuesta que no cumple el formato esperado
- **Cuando:** la función invoca al modelo
- **Entonces:** se rechaza esa respuesta y se devuelve un error controlado, no el dato inválido

### Escenario 3 — El proveedor tarda demasiado

- **Dado:** el simulador demorando más que el tiempo de espera configurado
- **Cuando:** la función invoca al modelo
- **Entonces:** la llamada se corta al cumplirse ese tiempo y devuelve un error controlado
