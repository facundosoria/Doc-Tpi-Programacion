## Descripción (Como / Quiero / Para)

- **Como:** docente autorizado de una cohorte
- **Quiero:** consultar mi banco de casos de referencia y sus entradas aunque el servicio se
  reinicie
- **Para:** confiar en que el dato de referencia que cargué persiste y puedo calibrar sobre él

---

## Notas / Observaciones

- **Reglas de negocio:** la consulta pide la misma autorización que la carga. El listado se muestra
  de a partes y viene ordenado del más nuevo al más viejo. El detalle incluye las entradas del banco
  de casos. Un banco de casos de otra cohorte **no aparece** en la respuesta.
- **Validaciones:** consultar un banco de casos que no existe avisa claramente que no se encontró
  (nunca un error genérico); pedir una parte del listado fuera de lo permitido se rechaza con un
  mensaje claro.
- **Datos obligatorios:** ninguno para consultar; opcionalmente se puede filtrar por versión de
  rúbrica y elegir qué parte del listado ver.
- **Performance:** el dato se guarda de forma que persiste entre reinicios; después de reiniciar el
  entorno, la consulta devuelve exactamente lo que se había cargado antes.
- **Seguridad:** sin el permiso adecuado, la consulta se rechaza; el filtro por cohorte se aplica
  siempre, nunca es opcional.
- **Accesibilidad:** no aplica en esta historia (la pantalla es H07).
- **Otros:** esta es la **historia candidata a canónica** del backlog: pequeña, entendida por todos
  y con un recorrido completo (permiso + lectura + persistencia). Su valor en puntos se fija en el
  Sprint 0 y queda como referencia de todas las demás.

---

## Criterios de Aceptación (CA)

- [ ] **CA1:** un banco de casos creado y con una entrada se puede consultar y devuelve esa entrada.
- [ ] **CA2:** después de reiniciar el entorno, la misma consulta devuelve los mismos datos.
- [ ] **CA3:** el listado respeta la parte pedida y el orden del más nuevo al más viejo.
- [ ] **CA4 (negativo):** el banco de casos de otra cohorte no aparece en el listado y su detalle
  avisa que no se encontró.
- [ ] **CA5 (negativo):** pedir el detalle de un identificador con formato válido pero que no existe
  avisa que no se encontró, nunca un error genérico.
- [ ] **CA6 (negativo):** pedir una parte del listado demasiado grande se rechaza con un mensaje
  claro.

## BDD

**Característica:** lectura del banco de casos con persistencia garantizada.

### Escenario 1 — La consulta sobrevive al reinicio (camino correcto)

- **Dado:** un docente que creó un banco de casos y le cargó una entrada
- **Cuando:** se reinicia el servicio y su base de datos
- **Y:** el docente vuelve a consultar el banco de casos
- **Entonces:** la respuesta trae el banco de casos y la entrada tal como se cargaron

### Escenario 2 — Aislamiento entre cohortes

- **Dado:** dos bancos de casos, uno de la cohorte del docente y otro de una cohorte ajena
- **Cuando:** el docente pide el listado
- **Entonces:** solo aparece el banco de casos de su cohorte
- **Y:** pedir el detalle del ajeno avisa que no se encontró

### Escenario 3 — Banco de casos inexistente

- **Dado:** un identificador con formato válido que no corresponde a ningún banco de casos
- **Cuando:** el docente consulta su detalle
- **Entonces:** el sistema avisa que no se encontró, sin mostrar un error genérico

### Escenario 4 — Parte del listado fuera de rango

- **Dado:** el listado con un límite razonable por página
- **Cuando:** el cliente pide una cantidad de resultados excesiva
- **Entonces:** el sistema rechaza el pedido y no devuelve datos
