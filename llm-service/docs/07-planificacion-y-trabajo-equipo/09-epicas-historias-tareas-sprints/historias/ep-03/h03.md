## Descripción (Como / Quiero / Para)

- **Como:** docente autorizado de una cohorte
- **Quiero:** una pantalla mínima para dar de alta, cargar y consultar el banco de casos de
  referencia
- **Para:** trabajar la referencia de mi curso sin depender de herramientas técnicas ni de llamadas
  manuales

---

## Notas / Observaciones

- **Reglas de negocio:** la pantalla hace el alta, la carga de entradas y la consulta **siempre a
  través de la plataforma**, nunca contra el servicio directo. Muestra quién está operando en cada
  momento.
- **Validaciones:** la conversación se valida antes de enviarse, con un aviso visible de que **no se
  interpreta como instrucciones**; los cinco puntajes aceptan valores entre 0 y 100.
- **Datos obligatorios:** la conversación y los cinco puntajes de referencia para cargar una
  entrada.
- **Performance:** la pantalla muestra un estado de carga visible mientras se resuelven las
  acciones, también para quienes usan lector de pantalla.
- **Seguridad:** si la acción no está autorizada, la pantalla lo muestra de forma explícita, no como
  un error genérico.
- **Accesibilidad:** cada campo tiene su etiqueta asociada, el grupo de puntajes está agrupado y
  descripto, los mensajes de error se anuncian a quien usa lector de pantalla, y toda la pantalla se
  puede operar solo con teclado.
- **Otros:** si el backend no está disponible, la pantalla avisa «no se pudo contactar al backend»,
  sin romperse.

---

## Criterios de Aceptación (CA)

- [ ] **CA1:** desde la pantalla, el docente crea un banco de casos, carga una entrada y la ve en el
  detalle, sin usar herramientas técnicas.
- [ ] **CA2:** todas las acciones pasan siempre por la plataforma, nunca directo al servicio.
- [ ] **CA3:** hay estados visibles de carga y de error en cada acción.
- [ ] **CA4 (negativo):** con el backend caído, la pantalla muestra un aviso claro y sigue navegable.
- [ ] **CA5 (negativo):** una conversación mal formada muestra un mensaje de validación y **no** se
  envía.
- [ ] **CA6 (negativo):** una acción no autorizada se refleja como «no autorizado» en la interfaz.

## BDD

**Característica:** interfaz docente mínima del banco de casos.

### Escenario 1 — Recorrido completo desde la pantalla (camino correcto)

- **Dado:** un docente autorizado con la pantalla abierta y el backend disponible
- **Cuando:** crea un banco de casos, carga una entrada con conversación y puntajes, y abre el
  detalle
- **Entonces:** la entrada aparece listada con sus cinco puntajes y sus pesos

### Escenario 2 — Backend no disponible

- **Dado:** el servicio de IA detenido
- **Cuando:** el docente abre el listado de bancos de casos
- **Entonces:** la pantalla muestra «no se pudo contactar al backend» y no queda en blanco ni con un
  error sin contexto

### Escenario 3 — Conversación inválida

- **Dado:** el formulario de carga de entrada
- **Cuando:** el docente pega un texto mal formado y confirma
- **Entonces:** la pantalla muestra un mensaje de validación y no envía el pedido

### Escenario 4 — Acción no autorizada

- **Dado:** un docente cuyo backend rechaza la acción por falta de permiso
- **Cuando:** intenta crear un banco de casos
- **Entonces:** la pantalla muestra el estado «no autorizado» con el detalle recibido
