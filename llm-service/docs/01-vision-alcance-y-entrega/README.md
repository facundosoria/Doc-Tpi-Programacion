# 01 — Visión, alcance y entrega

Esta carpeta explica **por qué existe `llm-service`, qué resuelve el MVP y qué queda fuera**. Es la
entrada adecuada después de Gobierno para entender el producto antes de pensar en clases, endpoints
o proveedores de modelos.

## Qué vas a encontrar

1. [Problema y alcance](01-problema-y-alcance.md): actores, problema pedagógico, capacidades y
   límites de las fases.
2. [Entregables y plan](02-entregables-y-plan.md): entregas esperadas, secuencia general y
   criterios de avance.
3. [Entregas y evidencias](03-entregas/README.md): checklist, planificación, verificación y
   coordinación preparados para momentos concretos de entrega.
4. [Alcance MVP vigente](../01-alcance-mvp.md): referencia corta para confirmar rápidamente qué
   entra, qué no entra y qué depende de otros equipos.

## Cómo leerla

Leé `01-problema-y-alcance.md` completo al llegar al equipo. Luego contrastá el alcance con
`01-alcance-mvp.md`. Consultá `02` cuando estés planificando y `03-entregas/` solo cuando necesites
evidencia, checklist o una coordinación asociada a una entrega.

Un documento de entrega puede mostrar una decisión o evidencia de un momento anterior; no sustituye
una regla vigente. Si cambian alcance o criterios, la corrección se resuelve en la fuente canónica
y se registra, no se agrega como una nota aislada al cierre de una entrega.
