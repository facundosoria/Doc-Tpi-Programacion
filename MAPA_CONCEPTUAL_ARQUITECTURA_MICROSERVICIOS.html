Las 7 Láminas de Arquitectura y Procesos en Detalle

Modelos conceptuales oficiales que resuelven los flujos transversales entre microservicios.

Reglas No Negociables y Decisiones de Arquitectura

Directivas fijas establecidas por la cátedra que definen el marco del TPI.

1

API Gateway: Única Puerta de Entrada

Ningún cliente accede a un microservicio por otro camino. Permite resolver autenticación, límites de uso y trazabilidad en un solo lugar.

2

Registro Dinámico con Service Discovery

No hay direcciones IP fijas escritas en configuración. Cada servicio informa su nombre lógico, ubicación y salud al arrancar.

3

Prohibida Comunicación Directa P2P

Si un microservicio necesita llamar a otro de forma sincrónica, sale y vuelve a entrar por el API Gateway para mantener trazabilidad y balanceo.

4

Base de Datos Exclusiva (Database-per-Service)

Cada servicio es dueño exclusivo de su base de datos. Nadie lee la tabla del vecino ni comparte esquema o credenciales de conexión.

5

Event-Driven Backbone para lo Asincrónico

Lo que no requiere respuesta inmediata viaja por el Bus de Eventos. El Tema 11 define el contrato único de mensajes para toda la plataforma.

6

Curso-Cohorte como Clave de Contexto

Casi ninguna entidad existe fuera de una cohorte. Monedas, inventario, rankings y progreso están estrictamente acotados a la cohorte activa.

Decisiones Abiertas que Afectan a Múltiples Equipos

1. Caída del Sandbox

El PRD define qué ocurre si el LLM no responde (nota neutra o cálculo diferido), pero no define la regla equivalente ante la caída del Sandbox en picos de cierre.

2. Transversales sin Dueño

Arquitectura multi-idioma (i18n), alcance de la versión móvil nativa vs responsive y marco global de observabilidad no tienen tema único asignado.

3. Desmatriculación a Mitad de Cuatrimestre

Qué ocurre con las monedas (T08), el inventario (T09) y el progreso (T10) de un alumno que se da de baja de un curso (T02). Afecta a 4 temas simultáneamente.

Guía de Uso del Mapa Conceptual

Este mapa conceptual interactivo reúne la arquitectura integral de la plataforma gamificada del TPI Programación IV basada en el PRD y la Propuesta de Arquitectura Backend.

Cómo interactuar con el mapa:

  • Hacer clic en cualquier microservicio para abrir el panel de inspección con sus 3 columnas de prioridad (Pedido para empezar, Para más adelante, Podría ser), base de datos, endpoints y eventos.
  • Seleccionar filtros de vista en la barra superior para aislar flujos específicos (Sincrónico con Gateway, Asincrónico con Event Bus, Evaluación/Sandbox/LLM, Economía XP vs Monedas, Backoffice PAR-XX o Identidad).
  • Usar el buscador para localizar componentes, tópicos o reglas rápidamente.
  • Arrastrar el canvas o hacer zoom con los controles inferiores o rueda del ratón.
  • Navegar entre las pestañas superiores para revisar la Matriz Cruzada de Dependencias, el Catálogo de Eventos, la Tabla de Parámetros PAR-01..24 y las 7 Láminas explicativas.
